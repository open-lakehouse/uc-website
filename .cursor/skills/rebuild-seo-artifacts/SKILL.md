# Rebuild SEO / GEO / AEO artifacts

The site publishes five files that search engines and LLMs use to discover and
cite it. All of them are generated by `bun run build`; none is committed or
edited by hand.

| URL                  | Built from                                                                      | Purpose                                                                                               |
| -------------------- | ------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `/llms.txt`          | [src/routes/llms[.]txt.ts](../../../src/routes/llms[.]txt.ts)                   | Curated, citable index ([llmstxt.org](https://llmstxt.org)): docs, pages, community links, every post |
| `/llms-full.txt`     | [src/routes/llms-full[.]txt.ts](../../../src/routes/llms-full[.]txt.ts)         | Full text of every blog post, then the homepage FAQ                                                   |
| `/robots.txt`        | [src/routes/robots[.]txt.ts](../../../src/routes/robots[.]txt.ts)               | Allows all crawlers; points at the sitemap and the llms files                                         |
| `/sitemap-index.xml` | [src/routes/sitemap-index[.]xml.ts](../../../src/routes/sitemap-index[.]xml.ts) | Points at `/sitemap-0.xml`                                                                            |
| `/sitemap-0.xml`     | [src/routes/sitemap-0[.]xml.ts](../../../src/routes/sitemap-0[.]xml.ts)         | Every page, for search-engine crawlers                                                                |

## Why they are always current

They are server routes that the build prerenders from the same data the pages
render. Vercel runs `bun run build` on every deploy, so production never serves
a stale index. There is no generator to remember to run and no generated file
to commit. `src/lib/discovery-files.ts` lists them with their `Content-Type`,
which `plugins/vercel-output.ts` sets on Vercel.

## Single sources of truth

- **Canonical origin**: `site` in [site.config.mjs](../../../site.config.mjs).
  Every absolute URL in the five files, `<link rel="canonical">`, and
  `og:image` derives from it.
- **Posts and authors**: `src/content/blog/**` and `src/content/profiles/**`
  (title, description, date, authors, topics). Topic labels come from
  `topicsFor` in `src/lib/blog.ts`.
- **Post URLs**: `/blogs/<id>/`, where the id is the post folder's slug (or
  its frontmatter `slug`) in lowercase, from
  [src/lib/post-id.mjs](../../../src/lib/post-id.mjs). Every URL in the five
  files, and every canonical tag, is lowercase.
- **Pages**: `staticPages` in [src/lib/pages.ts](../../../src/lib/pages.ts) plus
  every post. The sitemap lists them, and Vercel 301s their other letter cases
  to them.
- **Community links** (GitHub, Slack, Luma): `menus.headerCtas` in
  `site.config.mjs`. A rotated Slack invite only needs changing there.
- **FAQ**: `src/lib/faq.ts`, rendered by `Faq.tsx` and mirrored into
  `/llms-full.txt`.
- **Docs and page lists**: `DOCS`, `PAGES`, and `CTA_DESCRIPTIONS` in
  [src/lib/llms-render.ts](../../../src/lib/llms-render.ts). The docs site
  publishes its own `llms.txt`; link to it rather than copying docs content here.

## What to update when

| Change                                | Update                                                                                                               |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Add, edit, or remove a post or author | Nothing; rebuild. Give every post a `description`, since it is the summary in `/llms.txt`.                           |
| Add a page under `src/routes/`        | Add it to `staticPages` in `src/lib/pages.ts` (a test fails until you do) and to `PAGES` in `src/lib/llms-render.ts` |
| Add a header CTA                      | Add its label to `CTA_DESCRIPTIONS`                                                                                  |
| Use a new MDX component in posts      | Teach `toPlainMarkdown` in `src/lib/llms-render.ts` to flatten it                                                    |
| Change the production domain          | `site` in `site.config.mjs`                                                                                          |

## Regenerate and inspect

```bash
bun run build
cat .output/public/llms.txt .output/public/robots.txt
rg -c "^# " .output/public/llms-full.txt   # one heading per post, plus the FAQ
```

Or run `bun run dev` and open `/llms.txt` on the URL it prints.

## Check for dead links

[scripts/check-links.mjs](../../../scripts/check-links.mjs) has three modes:

| Command                | Checks                                                                                                 | When                                   |
| ---------------------- | ------------------------------------------------------------------------------------------------------ | -------------------------------------- |
| `bun run links`        | Every internal and external link in `src/` and `site.config.mjs`                                       | While editing; no build needed         |
| `bun run links:staged` | What is being committed                                                                                | Automatically, in `.husky/pre-commit`  |
| `bun run links:dist`   | After `bun run build`: every page, anchor, the sitemap, `robots.txt`, and both llms files in the build | Before a PR, and after changing routes |

The pre-commit hook fails only on dead links the commit adds, or creates by
deleting or renaming a page or image. Dead links already in untouched lines are
summarized, not blocking. External URLs are checked only on added lines.

- **Dead** (exit 1): an internal path with no page, file, or redirect; an
  `#anchor` with no matching heading or id; an external URL answering 404/410;
  a host that does not resolve.
- **Warning**: 401/403/429/999 (bot walls such as Slack invites, LinkedIn,
  and openai.com), timeouts, and 5xx. Open these in a browser.
- `--offline` (or `LINKS_OFFLINE=1`) skips external URLs. With no network,
  the check skips them automatically.
- External URLs that passed are cached for a week in
  `node_modules/.cache/check-links/`. Use `--no-cache` to recheck them.
- `--dist` checks the build as Vercel serves it: files match case-sensitively,
  and the redirects are those in `site.config.mjs` plus a 301 from any other
  letter case of each page in the sitemap (`src/lib/case-redirects.mjs`). It
  reads `.output/public` by default; pass `--dist .vercel/output/static` for
  the Vercel build. Links to `unitycatalog.io` and the `site` host are checked
  as internal paths.
- Add known false positives to
  [scripts/check-links.ignore](../../../scripts/check-links.ignore), with a
  reason. `SKIP_LINK_CHECK=1 git commit` bypasses the hook once.

Fix a dead internal link by pointing it at the post's current, lowercase
`/blogs/<id>/`. When an old URL may still have inbound links, also add a
`redirects` entry in `site.config.mjs`, in lowercase; `plugins/vercel-output.ts`
writes it into Vercel's `config.json` as a 301. A page's URL in another letter
case needs no entry: Vercel 301s it to the lowercase URL. Only `links:dist`
sees table-of-contents anchors, since they are generated at render time.

## Verification checklist

- [ ] `bun run build && bun run links:dist` exits 0, or every remaining dead link was there before your change.
- [ ] `.output/public/llms.txt` lists new or changed posts with a description and the right date and topics.
- [ ] `.output/public/llms-full.txt` has no leftover MDX (`rg -n "^import |<Journey|<LikeC4View" .output/public/llms-full.txt` prints only code-block lines).
- [ ] Every URL in the discovery files uses the `site` origin: `rg -o "https?://[^/]+" .output/public/llms.txt .output/public/robots.txt .output/public/sitemap-0.xml | sort -u`.
- [ ] `bun run lint` and `bun run format` pass on edited files.
